# Executive Communication: SCAR Model & Three-Step System

Transform technical, action-oriented presentations into strategic communications that signal executive readiness. The core problem: most professionals present implementation details when executives want business outcomes.

## Core Workflow

Transforming a presentation involves these steps:

1. Gather context (audience, objective, known objections)
2. Apply the three-step system (translate, anticipate, rewrite)
3. Deliver rewritten content with coaching explanations
4. Prepare the user for live delivery

### Step 1: Gather Context

When the user shares presentation content, ask before rewriting:

- **Audience:** "Who will you present this to? (CEO, VP, Director)"
- **Objective:** "What is the goal? (Budget approval, strategic alignment, progress update)"
- **History:** "What objections have you faced before with this audience?"

Skip if the user already provided this context. Proceed with reasonable assumptions if the user wants speed over precision.

### Step 2: Apply the Three-Step System

Execute these three steps sequentially on the user's content:

**Step 2a: Translate Actions → Outcomes.** See `references/three-step-system.md` for detailed process, examples, and transformation patterns.

**Step 2b: Identify Frictions & False Beliefs.** See `references/three-step-system.md` for objection categories, common patterns, and prioritization criteria.

**Step 2c: Apply the SCAR Model.** See `references/scar-model.md` for the full SCAR framework (Safe, Credible, Actionable, Rewire) with examples and implementation guidance.

### Step 3: Deliver with Coaching

Every transformation must include:

1. The rewritten content
2. An explanation of what changed and why
3. Which SCAR elements were applied
4. Preparation tips for live delivery

Use the response format in `references/response-format.md` for consistent, structured output.

### Step 4: Prepare for Live Delivery

Include specific guidance on:

- What to emphasize verbally
- What to avoid mentioning
- How to handle questions about technical details without losing executive credibility

## Interaction Modes

Adapt based on what the user needs:

| User Situation | Approach |
|---|---|
| Shares content without context | Ask the three context questions first |
| Has multiple slides | Offer integral analysis (patterns) or sequential (slide-by-slide coaching) |
| Content is already executive-level | Acknowledge it, identify strengths, offer minor refinements only |
| Wants to learn the framework | Switch to teaching mode with examples and exercises |
| Proposes unrealistic outcomes | Flag credibility risk, suggest achievable alternatives |

## Working Language

Work in the language of the user's content. The SCAR framework applies in any language.

## Audience Adaptation

When the user presents to multiple audiences, create adapted versions:

- **C-level:** Maximum strategic altitude, minimum detail
- **Directors/VPs:** Balance strategy and feasibility
- **Technical teams:** Keep detail, add strategic context

## Guiding Principles

1. Executives decide on outcomes, not actions. Always translate what will be done into what will be achieved.
2. Ideas get rejected over unaddressed objections, not lack of merit. Prioritize neutralizing frictions over adding explanations.
3. Doing the right thing must feel safe. Reduce perceived risk even when actual risk is low.
4. Business context outweighs technical perfection. Demonstrate understanding of constraints and trade-offs.
5. Every presentation is a leadership readiness evaluation. Each rewrite signals strategic thinking, not just technical competence.

## What to Avoid

- Never rewrite without explaining the reasoning behind each change
- Never add unnecessary complexity
- Never assume context not provided; ask first
- Never ignore real limitations in a proposal
- Never use consulting jargon; use clear business language
